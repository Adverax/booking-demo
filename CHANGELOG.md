# Changelog

## 2026-10-22
- CARD-007 (feature): Added booking validation in a fixed order before any insert: an empty customer name or a slot start not on the UTC half hour is 400 validation_error (the temporary flooring of an unaligned start is removed), an unknown resource is 404 not_found, a slot outside the resource's working hours (read through the catalog) is 422 slot_outside_working_hours, and a slot starting before the injected clock's now (equal is accepted) is 422 slot_in_past unless the idempotency key is stored, in which case one key read returns the original booking (same payload) or 409 idempotency_key_conflict; the normal booking path makes no key read, and the bookSlot contract text states this order.
- CARD-005 (feature): Added idempotent booking replay with insert-then-classify: an empty idempotency key is rejected with 400 validation_error before anything is stored, and on a unique-index rejection one separate autocommit read of the booking under the key decides the answer — the same payload (resource, canonical slot start, customer name compared byte for byte) returns the original booking in its current state with 200 (also after cancellation and after the slot has started), a different payload is 409 idempotency_key_conflict, and no booking under the key is 409 slot_taken.
- CARD-004 (feature): Added cancelling a booking by its id with one autocommit update (a repeated cancel returns the same cancelled booking, an unknown id is 404 not_found) and reading a booking by id, and made cancellation final twice over: a domain guard and a schema trigger (migration 0002) that aborts any update from cancelled to another status, answered as 409 booking_cancelled.
- CARD-006 (feature): Added full validation of resource creation (a name, weekly working hours with at most one half-hour-aligned interval per weekday inside one UTC day, where 24:00 is allowed only as an interval end), answered with a 400 validation_error before anything is stored, plus listing resources and reading one by id with a 404 not_found for an unknown id.
- CARD-003 (feature): Added the service bootstrap (environment configuration, store open with migrations, HTTP server with timeouts and graceful shutdown), minimal resource creation, and booking of one slot as a single autocommit insert where the slot uniqueness index picks exactly one winner among concurrent requests and the others get a slot_taken conflict.
- CARD-001 (feature): Added the OpenAPI contract for resources, availability and bookings with one stable set of error codes, and the generated net/http server interface mounted on http.ServeMux with JSON error responses for malformed requests.
- CARD-002 (feature): Added the SQLite store with WAL, busy timeout and foreign keys, and embedded schema migrations that create the resource and booking tables with the slot and idempotency-key uniqueness indexes on startup.
